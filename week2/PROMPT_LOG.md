## 记录 2｜05 题：把 1 判成了素数

- **场景**：找 Bug 思路
- **触发方式**：**AI 主动指出**（我并没有专门提问，是拆分后跑用例时发现的）
- **我原来的写法**：

  ```cpp
  if (a <= 0) return 0;
  if (a == 1 || a == 2) return 1;
  ```

- **问题**：素数定义是「**大于 1**，且只能被 1 和自身整除」，所以 `1` 不是素数。
  我原来把 `1` 和 `2` 一起特判成素数，`1` 就判错了。
- **AI 给的改法**：

  ```cpp
  if (a < 2) return 0;   // 0、1 和负数一律不是素数
  ```

  去掉原来那两行特判，`2` 会自然走进循环（`i = 2; 2 < 2` 不成立），最后返回 1，结果仍然正确。
- **我的验证**：输入 `1` → not a prime number；`2` → prime；`7` → prime；`9` → not prime。
- **我的理解**：特判写得越「聪明」越容易漏边界。凡是「小于 2 一律排除」这种一刀切的条件，
  比逐个列举特殊情况更不容易出错。
- **是否采纳**：采纳。

## 记录 3｜06 题：最大公约数求成了最小公约数

- **场景**：找 Bug 思路
- **触发方式**：**AI 主动指出**（跑 `gcd(12, 18)` 用例时发现返回 2，正确答案是 6）
- **我原来的写法**：

  ```cpp
  for (int i = 2; i <= m; i++) {
      if (a % i == 0 && b % i == 0) return i;
  }
  ```

- **问题**：从 `2` 开始**往大**找，第一个满足条件的 i 就是「**最小**公约数」，
  不是最大公约数。比如 `gcd(12, 18)`：i=2 时 12 和 18 都能被 2 整除，直接返回 2，可正确答案是 6。
- **AI 给的改法**：

  ```cpp
  for (int i = m; i >= 2; i--) {
      if (a % i == 0 && b % i == 0) return i;
  }
  ```

  从大到小找，第一个命中的就是最大的那个。`m` 取 `a`、`b` 的较小值，因为公约数不可能超过它。
- **我的验证**：`12 18` → 最大公约数 6、最小公倍数 36。
- **我的理解**：这题和最小公倍数正好相反——求「最小」的要从下往上找，求「最大」的要从上往下找。
  我最小公倍数那半边写对了（从 `max(a,b)` 往上找），最大公约数这半边方向写反了。
- **是否采纳**：采纳。

## 教师抽查访谈 · 我能当面讲清的三个问题

1. **为什么 1 不是素数？**
   → 素数要求「大于 1」且只有 1 和自身两个正因数；1 只有一个正因数（它自己），所以不是素数。

2. **为什么求最大公约数要从大到小枚举？**
   → 从小到大找到的第一个是「最小」公约数；要找最大，必须从可能的最大值（`min(a,b)`）往下找。

3. **`unsigned short` 里 `-1` 为什么变成 65535？**
   → 无符号类型没有负数，`-1` 按补码被解释成该类型能表示的最大值，`unsigned short` 是 16 位，最大值 65535。
